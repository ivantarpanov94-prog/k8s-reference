Cluster Architecture: Master vs. Worker

Master Node (Control Plane)

Role: Acts as the control center, managing overall operation and coordination of worker nodes.

Key Components:
  • etcd: Key-value store maintaining cluster state (nodes, containers, configuration).
  • Kube API Server: Central management interface facilitating all communication and operations.
  • Scheduler: Assigns pods to optimal nodes based on resources and constraints.
  • Controllers: Operational background workers ensuring desired state (e.g., replication, node availability).

Worker Node

Role: Responsible for running application containers and executing workloads assigned by the master node.

Key Components:
  • Kubelet: The "captain on ship"—manages container lifecycle and reports status back to Kube API Server.
  • Kube Proxy: Manages networking rules for seamless communication between containers and external traffic.
How Components Work Together:
  • Master oversees Worker: Master coordinates high-level scheduling and resource allocation across workers.
  • etcd informs decisions: State data in etcd allows the Scheduler and Controllers to make runtime decisions.
  • API Server is the hub: All Master-to-Worker communication routes through the Kube API Server.
  • Kubelet dialogue: Kubelet continuously polls the Kube API Server for instructions and reports node/pod health back.

The Steam Analogy:

  • Docker (registry/library) — Steam library holding game titles (images)
  • 1 game = 1 Docker image — single application recipe
  • Deployment — rule maintaining target replica count
  • Pods — active running copies of a game
  • Nodes — compute resources (VMs) hosting pods
  • Kubernetes — conductor orchestrating workloads across nodes
