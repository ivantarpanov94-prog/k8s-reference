🌿 Git Version Control Reference

Essential commands, core lifecycle operations, branching workflows, and conflict management for your daily DevOps engineering.

⚙️ 1. Core Lifecycle & Remote Commands

The foundational commands used to initialize repositories, stage changes, commit history, and sync with remotes:

  • Initialize or Clone: Start a new local repository or clone an existing remote one. 
    # Initialize a new local Git repository
git init

# Clone an existing repository from remote
git clone
  • Check Status & Stage Changes: Inspect working tree status and stage modified or new files. 
    # Check current status of working directory and staging area
git status

# Stage specific files or all changes
git add filename.txt
git add .
  • Commit Changes: Record staged changes into the local repository history with a descriptive message. 
    git commit -m "feat: add initial project structure and documentation"
  • Push & Pull (Remote Sync): Send your local commits to a remote repository or fetch and integrate upstream changes. 
    # Push local branch commits to remote repository
git push origin main
# (or git push -u origin feature-branch on first push)

# Fetch and merge changes from the remote repository
git pull origin main

📁 2. Managing Files (Create, Edit, Delete)

How to manage individual files directly within your working tree:

  • Create / Add a new file directly: Create an empty file via terminal or write content directly. 
    touch index.html
# Or write directly into a file:
echo "Hello DevOps" > README.md
  • Edit files: Modify existing files using your favorite editor (e.g., VS Code, nano, vim), then stage the modifications. 
    nano README.md
# Stage the edited file for commit:
git add README.md
  • Delete files: Remove files from both the working directory and git tracking. 
    # Delete and stage removal:
git rm unwanted-file.txt

# Or if already deleted locally, stage all deletions:
git add -u

📜 3. Git Log & Detailed History

The git log command is essential for reviewing commit history. Adding patch flags provides detailed line-by-line output on what changes were made.

# View commit history with detailed patch diffs per commit:
git log -p

# View a compact, one-line graphical history:
git log --oneline --graph --decorate

🔀 4. Branches & Merge Requests

When creating a merge request, you create a feature branch, push it to remote, and open a request to merge into master/main. Always sync your local branch afterward.

# Create and switch to a new feature branch:
git checkout -b feature/new-dashboard
# (or: git switch -c feature/new-dashboard)

# Push branch to remote repository:
git push -u origin feature/new-dashboard

# After your Merge Request is approved and merged:
git checkout main
git pull origin main

📈 5. Rebasing Your Branch

Rebasing your branch means taking your local changes and replaying them on top of the latest main branch. This maintains a clean, linear project history and simplifies merging.

# Update your local main and rebase your current feature branch:
git checkout main
git pull origin main
git checkout feature/new-dashboard
git rebase main

⚠️ 6. Resolving Merge Conflicts

When changes in your branch conflict with main, Git pauses the merge/rebase so you can resolve them manually.

# 1. Check which files have conflicts:
git status

# 2. Open conflicted files, remove conflict markers (<<<<<<<, =======, >>>>>>>), 
# and keep the desired code.

# 3. Stage resolved files and continue:
git add 
git rebase --continue   # (or git merge --continue)

⎌ 7. Rollback & Reverting Changes

If you need to safely undo a published commit without rewriting public history, use git revert after locating the commit ID via git log.

# Find commit hash:
git log --oneline

# Create a new commit that reverses the specified commit:
git revert
